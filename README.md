# 🛡️ CyberSec Incident Manager

A SOC-style incident management dashboard built with **Streamlit** and **MySQL/MariaDB**. It lets security analysts log, assign, investigate, and report on cybersecurity incidents, with all data stored in a normalized relational database.

---

## Features

| Module | What it does |
|---|---|
| **Login** | bcrypt-hashed demo authentication gate |
| **Dashboard** | KPI cards and Plotly charts (severity, status, recent incidents) |
| **Incidents** | Create, filter, assign analyst, update status |
| **Assets & Vulnerabilities** | Asset inventory, CVE/CVSS records, link them to incidents |
| **Investigation** | Evidence log (with file hash), mitigation actions, comments, status history timeline |
| **Reports** | Incidents by attack type / severity / month, analyst workload, full report, CSV export, saved reports |
| **Administration** | Manage users, analysts, attack types, system info |

---

## Tech Stack

- **Frontend / App:** Streamlit
- **Database:** MySQL / MariaDB (InnoDB, utf8mb4)
- **ORM / Driver:** SQLAlchemy 2.x + PyMySQL
- **Analytics:** pandas, Plotly
- **Security:** bcrypt

## Database Design

Database: `cyber_incident_db` (14 tables)

**Core entities:** `users`, `analysts`, `incidents`, `assets`, `vulnerabilities`, `attack_types`, `incident_status`

**Relationship / junction tables:** `incident_assets`, `incident_vulnerabilities` (many-to-many)

**Investigation tables:** `evidence`, `mitigation_actions`, `incident_comments`, `incident_status_history` (audit trail)

**Reporting:** `reports`

Key relationships:
- `incidents` → `users` (reported_by), `analysts` (assigned_analyst), `attack_types`, `incident_status`
- `analysts` → `users` (1:1)
- Child tables use `ON DELETE CASCADE` on `incident_id`
- Seeded: 6 statuses (Open → Assigned → Investigating → Contained → Resolved → Closed) and 10 attack types (Phishing, Malware, Ransomware, SQL Injection, DDoS, etc.)

## Getting Started

### Prerequisites
- Python 3.9+
- MySQL or MariaDB server running locally

### Installation

```bash
# 1. Start the database
sudo systemctl start mariadb

# 2. Clone / enter the project
cd cyber-incident-manager

# 3. Create a virtual environment and install dependencies
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 4. One-time setup (asks for MySQL root credentials)
python setup.py

# 5. Run the app
streamlit run app.py
```

Open **http://localhost:8501**.

`setup.py` will:
1. Create the database `cyber_incident_db`
2. Create the application user `cyber_app` with limited privileges (SELECT, INSERT, UPDATE, DELETE)
3. Import `database/schema.sql`
4. Generate `.streamlit/secrets.toml` with the DB credentials and the bcrypt hash of the demo password

## Sample Queries

```sql
-- Incidents with status and attack type
SELECT i.incident_code, i.title, i.severity, s.status_name, a.attack_name
FROM incidents i
JOIN incident_status s ON i.status_id = s.status_id
LEFT JOIN attack_types a ON i.attack_type_id = a.attack_type_id;

-- Incident count by severity
SELECT severity, COUNT(*) AS total FROM incidents GROUP BY severity;

-- Status change audit trail
SELECT h.incident_id, o.status_name AS old_status, n.status_name AS new_status,
       u.full_name AS changed_by, h.changed_at
FROM incident_status_history h
LEFT JOIN incident_status o ON h.old_status_id = o.status_id
JOIN incident_status n ON h.new_status_id = n.status_id
JOIN users u ON h.changed_by = u.user_id;
```

## Troubleshooting

| Problem | Fix |
|---|---|
| `mariadb.service failed` | `sudo journalctl -xeu mariadb.service`, check data dir permissions and port 3306 |
| `Access denied` for root in setup | Set a root password: `sudo mysql -e "ALTER USER 'root'@'localhost' IDENTIFIED BY 'yourpass'; FLUSH PRIVILEGES;"` |
| Broken `.venv` after copying project | `rm -rf .venv` and recreate it |
| App can't connect | Check `.streamlit/secrets.toml` and that the DB is running |

## Security Notes

- Passwords are stored as bcrypt hashes
- The app connects with a least-privilege DB user (no DDL rights)
- Queries go through SQLAlchemy with bound parameters
- Evidence records store a SHA-256 file hash field for integrity tracking
